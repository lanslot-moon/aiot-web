# OTA 正式页面接入说明

## 页面入口

- 项目侧栏 → OTA 升级 → 固件管理：选择产品后管理模块、版本和升级包。全量包完成文件登记或差分构建成功后自动签名封存，操作员选择样机后启动验证。验证通过可带入当前升级包创建批次。支持未发布产品提前准备固件。
- 项目侧栏 → OTA 升级 → 升级批次：批次列表、四步创建、草稿激活、暂停/恢复/停止、灰度与推送速率调整、设备任务及每轮记录。创建批次仍限定已发布产品。
- 产品详情的「OTA 固件」仅为快捷跳转，携带产品进入同一 OTA 工作区；批次详情的升级包链接也在此工作区打开。固件管理统一使用 /projects/:projectId/ota?section=firmware&product=…，模块、版本、包通过查询参数定位。
- 全程使用正式请求客户端，携带项目上下文，不从原型数据或浏览器本地缓存模拟业务成功。
- 说明集中在点击问号；更多匹配条件和高级推送策略按需展开。

## 后端查询与分层

新增能力直接放入已有领域接口，不存在 ConsoleQuery 接口或服务：

| 服务内地址 | 所属接口 | 用途 |
| --- | --- | --- |
| GET /ota/releases | IOtaReleaseApiService | 批次列表，关联名称整页批量读取 |
| GET /ota/releases/{id}/configuration | IOtaReleaseApiService | 批次和当前规则的一致快照 |
| GET /ota/verifications?packageId=… | IOtaVerificationApiService | 包关联的验证记录 |
| GET /ota/delta-builds/by-package/{packageId} | IOtaDeltaBuildApiService | 刷新后恢复唯一构建任务 |

分页统一传 `cursor`、`pageSize`（默认 20、最大 200），前端原样传递 `nextCursor`。参考 CommandExecutionBizService.cursorPage：Biz 层负责解码、取 pageSize+1、裁剪、hasMore、编码及 ICursorResult 组装。Repository 和 Mapper 只接受解码后的 afterId 与 limit 并返回 List。Service 不编解码或截取分页。模块、版本、包、设备任务、执行记录、批次与验证记录均按此分层。

批次、验证新增查询索引写入 OTA 的 schema-mysql.sql。构建与执行记录 ID 在 API VO 中使用字符串，避免 JavaScript 精度丢失。

## 接口发布配置

浏览器访问 `/api/v1/ota/**`。服务端当前契约为 `/ota/**`，网关清单位于后端仓库 `deploy/koupleless/gateway/ota-ingress.yaml`，重写到服务内地址。Higress 注解依据：https://higress.io/en/docs/latest/user/annotation/ 。

42 个后台接口直接登记在 IAM 唯一目录 `aiot-iam-infrastructure/src/main/resources/db/scoped-rbac-api-resources.sql`，使用已有 `ota:view/create/update` 权限，没有另外建立补充登记脚本。设备/App 接口不加入本次管理页面登记。

环境更新时需发布后端、执行统一 IAM 目录、失效 API_RESOURCE 缓存，并把 `ota-dev-protected` 加入现有认证插件 required 路由规则，再应用网关清单。文件上传另需已有 file:upload 权限。后端需要匹配的 Ed25519 签名密钥对，差分构建另需配置差分工具和文件服务。

## 验证边界

已进行前端类型检查、生产构建、零警告 lint，以及使用真实页面组件和受控 HTTP 响应的浏览器交互检查。覆盖四步创建、草稿不自动激活、19 位 ID 原样传递、桌面/390px 布局。该检查不代表已在实际设备执行 OTA。

后端执行 Maven validate 和跳过测试的 compile；按后端仓库约定未新增或运行测试。

## 后续接口补齐

- 停止批次：ACTIVE、PAUSED 状态且具备 ota:update 权限时可操作，确认后调用 POST /ota/releases/{releaseId}/stop。成功后更新详情并失效列表缓存；失败保留弹窗供重试。STOPPED 显示为“已停止”，支持列表筛选，不提供恢复或灰度修改入口。
- 差分构建每轮记录：打开抽屉时调用 GET /ota/delta-builds/{taskId}/attempts，一次读取该任务记录，不逐行补查。展示执行代次、状态、耗时；详情展示窗口内序号、起止时间、退出码、超时标记、结果说明和记录 ID。存在 RUNNING 记录时每 3 秒刷新，关闭抽屉后停止查询。
- 验证信息：列表展示创建时间与清单一致性，点击信息按钮查看绑定摘要和升级包 ID。清单不一致时，历史 PASSED 记录不能作为当前包的验证结果。
- 已用受控 HTTP 响应检查停止的取消、失败重试、成功状态与筛选，以及构建记录按需加载、失败重试、退出码 0、清单不一致提示和 390px 布局；这些检查未调用真实升级设备。
