# OTA UX 审查与交互定稿

## 用户确认的后台流程

当前页面面向管理员。固件模块、版本、全量包／差分构建、封存和样机验证由产品内「固件与升级」完成。进入 OTA 后台后，流程为选择目标版本和升级包 → 选择升级范围与匹配条件 → 配置时间、推送、确认、速率与重试策略 → 提交升级批次 → 云端匹配设备并建立任务 → 满足下发条件 → 设备执行 → 管理员查看结果。

### 后台页面结构

创建升级批次采用四步向导「选择固件 → 升级范围 → 升级策略 → 检查并提交」。从产品升级包进入时预填第一步，保留核对及修改入口。项目级 OTA 展示批次与设备任务，批次详情提供摘要、真实状态统计、设备明细及按状态可用的操作。

### 策略表单

| 配置 | 管理员交互 | 当前接口对照 |
| --- | --- | --- |
| 发布时间 | 立即生效／定时生效，可设置结束时间 | effectiveFrom、effectiveUntil，沿用静态批次预约约束 |
| 设备执行时间 | 立即执行／指定时间 | 使用静默执行语义及 execTime |
| 任务获取方式 | 云端主动推送／设备主动获取，作为批次策略选择 | 当前 CreateReleaseVO 未发现对应开关，落地前需明确配置契约 |
| 下发确认 | 直接下发／业务确认后下发，默认直接下发 | requireAppConfirm=true 创建 WAIT_CONFIRM，后台单个／批量确认接口推进到 WAIT_DISPATCH；界面使用业务确认文案 |
| 推送速率 | 固定速率／按成功数量递增 | 已有速率、阈值、增量及上限字段 |
| 自动重试 | 跟随服务策略；批次自定义时配置次数和间隔 | 当前 OtaRetryPolicy 使用服务配置，创建批次接口未发现重试参数；实际值需权威查询 |
| 手工重试 | 任务列表按适用状态选择并提交 | 已有批量重试接口 |

任务获取方式是管理员的策略配置。界面通过「等待下发」「等待设备获取」「已通知」「执行中」等真实状态说明进展，具体状态标签需要服务端事实支撑。后台采用静默执行语义，业务确认按管理员的选择写入 requireAppConfirm。选择业务确认后，在待确认任务列表提供单个和批量「确认下发」操作。App 页面、用户提醒、强制弹窗和主动检查入口均移出本后台交互范围。

「提交升级批次」在实现上顺序保存草稿并激活。创建成功后保留返回的批次 ID，激活失败时进入该批次详情显示「草稿已保存，激活失败」，提供「重试激活」。只有确认激活成功才显示「批次已提交」。可另提供次级操作「仅保存草稿」。

### 制包与执行反馈

全量包上传目标固件文件；差分包提供源和目标固件，后台完成生成差分、还原校验和上传产物。界面按接口真实状态展示构建进度，构建完成后继续文件核验、封存和样机验证。

计划生效、任务建立、通知或获取、设备执行、最终结果分别展示。下载到 100% 后继续等待校验、安装和结果确认。设备等待执行时间或条件时仅展示服务端明确的原因。管理员可查看异常、任务重试和历史执行轮次。

以上是当前后台设计范围及字段对照，优先于审查记录中描述的旧原型行为。

## 页面与操作设计

### A. 产品内入口

产品功能栏增加「固件与升级」。沿用现有产品页头、局部导航和 Card 样式。进入后第一屏显示模块表及「新增固件模块」，当前产品来自路由。

空状态标题为「还没有固件模块」，说明「为主控、通信模组等独立升级单元建立模块」，主按钮为「新增固件模块」。创建弹窗包含模块名称、模块标识、固件通道三个字段，通道帮助文字为「与设备上报的 OTA 通道一致，同一产品内唯一」。提交成功进入该模块版本列表，失败保留输入。

模块列表展示名称、标识、通道、状态。模块名称可打开版本列表。模块下展示版本号、版本状态、版本说明、更新时间，主操作为「新增固件版本」。版本详情页头常驻产品、模块与版本号，正文显示升级包列表。以面包屑和返回链接逐层返回，列表筛选与游标可恢复。

### B. 新建版本与升级包

新增版本表单先填写版本号、更新说明。硬件约束放在展开区域，依据正式 schema 提供输入和校验。后端只有 JSON 字段而没有明确结构时，使用有格式校验的高级输入，标注结构尚需契约确认。

保存版本后进入详情，主操作为「添加升级包」。包类型使用整包／差分包单选，每个选项下给一句适用说明。一个目标版本可管理多个包。表格展示包类型、来源版本、包状态、创建时间和查看操作，验证状态仅在能读取关联验证事实时展示。

制包采用四步页面，步骤名称为「包信息 → 文件准备 → 签名与封存 → 样机验证」。步骤完成后可查看已提交的信息。

| 步骤 | 交互 | 完成条件 | 出错后动作 |
| --- | --- | --- | --- |
| 包信息 | 整包默认选中。目标版本从详情带入。差分展开来源版本、源镜像 SHA-256、算法 | 创建包接口返回包 ID | 在字段附近提示错误，保留输入 |
| 文件准备 | 全量包上传目标完整文件。差分提供源、目标固件，提交后台生成差分、还原校验和产物上传 | 文件上传确认成功且已关联，或构建成功并核对实际文件关联结果 | 分别显示继续上传、重试确认、重试关联或重试构建 |
| 签名与封存 | 展示文件清单、摘要及签名输入，主按钮「校验并封存」按顺序登记签名并调用封存 | 服务返回已封存状态 | 签名失败定位签名字段，文件清单仍可查看 |
| 样机验证 | 选择当前产品测试设备，显示已选名单，创建后「开始验证」 | 读取验证结果为通过 | 打开失败设备任务；可重新创建验证 |

平台生成差分包时，源、目标固件关联须一致。分别选择源完整文件和目标完整文件，界面用文件名、大小及摘要帮助核对。上传文件入口可获得权威文件 ID，已有文件选择只在服务提供查询时启用。

包类型和基础版本在创建前可改。创建后按当前契约继续补文件和封存；需要换类型或基础版本时，通过「新建升级包」建立独立包。文件清单改变后重新获取摘要和签名。已有版本发布状态、包封存状态、验证状态分别展示。

### C. 创建升级计划

从验证成功页或版本详情中的升级包进入。页头显示当前产品、模块、目标版本、包类型和差分来源版本。将已知上下文带入向导，减少重复选择。

向导分为「选择固件 → 升级范围 → 升级策略 → 检查并提交」四个步骤。从产品内部进入时预填固件与升级包。

**升级范围**

先选「固定设备范围」或「持续匹配设备」。辅助文案分别为「激活时固定候选设备名单」与「发布生效期间持续匹配满足条件的设备」。

范围条件用「增加条件」按需添加指定设备、静态分组、设备标签、来源版本、硬件版本。当前产品固定在条件摘要中，其他条件取交集。标签行包含键和值，可删除条件；来源版本用可多选的值，差分包的来源限制单独显示。设备选择支持当前产品内查询、分页和已选数量，切换筛选保留已明确选中的设备，删除通过已选区域完成。

灰度比例放在范围条件之后，默认建议 5%，提供数字输入及 5%、10%、50%、100% 快捷选项。显示「对满足上述全部条件的设备应用灰度」。无候选统计时，摘要显示条件与比例，人数等待匹配结果。用户设置 0% 时显示「当前比例不会命中设备」。

**升级策略**

按使用顺序组织为「发布时间」「设备升级方式」「下发速度」，每组有简短标题。

| 控件 | 默认与展开 | 交互规则 |
| --- | --- | --- |
| 发布时间 | 默认立即生效；定时展开开始时间和可选结束时间 | 标明当前时区和 UTC 偏移；提交前重新校验相对当前时间的限制 |
| 任务获取方式 | 云端主动推送／设备主动获取 | 按正式配置契约接入，内部采用后台静默执行语义 |
| 设备执行时间 | 立即执行／指定时间 | execTime 为 0 或指定时间戳 |
| 下发确认 | 默认直接下发，可选择业务确认后下发 | 待确认任务通过后台单个或批量「确认下发」推进 |
| 下发速度 | 固定／按成功数量递增，默认固定 | 输入单位常驻为台／分钟。递增展开成功阈值、每档增量、最大速率 |
| 优先级 | 高级设置，默认 0 | 显示 0–100 限制及「影响待下发任务的顺序」 |

将固定范围切换为持续匹配时，若已配置预约开始时间，先在切换处说明将清除预约并让用户确认，再变更控件及字段。上一步保留当前填写，关闭整个未保存向导时使用已有草稿离开提示。

若设备执行时间早于发布开始时间，提供可见提示并让用户调整或明确保留；最终参数合法性按服务契约判断。所有确认摘要显示完整日期和时区，避免仅显示「明天凌晨」等相对时间。

**检查并保存**

确认页按照「升级内容」「设备范围」「时间与方式」「速度」四个紧凑区块排列，每块有「修改」链接返回对应步骤。差分版本显示来源到目标的箭头关系。100% 使用明确文字「全部符合条件的设备」，展示任务获取方式与设备执行时间。

主按钮为「提交升级批次」，次级操作为「仅保存草稿」。提交依次保存并激活，部分成功时按上文恢复已有批次。

### D. 计划监控与设备任务

计划详情依次显示标题与状态、范围和策略摘要、任务计数、设备明细。每个状态统计必须有权威数据来源。计划的状态操作集中在页头，激活、暂停、恢复依据当前状态切换。扩灰弹窗显示原比例与新比例，保留暂停状态；调速弹窗回读已有参数。

设备明细展示设备、状态、阶段、进度、轮次及更新时间。点开右侧 Sheet 才读取详细执行记录。进度 100% 配合「等待重启确认」等阶段描述，终态使用后端结果。

勾选后出现批量操作条，显示「已选 N 台」和清空选择。确认、取消、重试按全部选中任务是否符合条件启用。混合状态导致不可操作时，给出文字原因，例如「2 个任务正在执行，无法取消当前选择」。用户可用状态筛选重新选择，提交范围限于明确选中的任务。
