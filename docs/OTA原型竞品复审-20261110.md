# OTA 原型竞品复审

## 目标与证据

审查对象：当前 ota-console.html 管理员交互原型。保留产品内固件管理、后台升级批次和设备任务范围；不加入 App 用户流程。

证据：source（当前原型源文件、CreateReleaseVO.java）；Manual（基于官方文档提出的交互建议）。本轮完成源码检查与公开官方文档检索，没有登录厂商控制台，没有新增浏览器、axe 或 Lighthouse 检查。上轮浏览器结果不能证明本轮建议已实现。

## 官方参考

- 阿里云：[验证升级包](https://www.alibabacloud.com/help/en/iot/user-guide/verify-an-update-package)：按源版本筛选验证设备，查看验证进度，验证后进入批量升级。
- 阿里云：[批量升级](https://www.alibabacloud.com/help/en/iot/user-guide/initiate-a-batch-update)：静态与动态范围、目标范围和升级策略分步配置。
- 阿里云：[OTA 概述](https://www.alibabacloud.com/help/en/iot/user-guide/ota-upgrade-overview)：目标版本上报决定成功，进度 100% 不等于成功。
- 涂鸦：[固件升级](https://developer.tuya.com/cn/docs/iot/firmware-upgrade-operation-guide?id=K93ixsft1w3to)：固件与通道关联、测试设备验证、按比例逐步扩大灰度、暂停恢复、设备升级明细与发布统计。参考新版流程，不引入旧版审核等待规则。
- 移远：[固件 OTA 升级](https://developer.quectel.com/doc/quecpython/Application_guide/zh/firmware-upgrade/firmware-ota.html)：全量与差分区别、型号支持差异、源固件匹配要求。
- 移远：[OTA 常见问题](https://developer.quectel.com/doc/quecpython/Application_guide/zh/firmware-upgrade/firmware-ota-issues.html)：差分源与目标分区一致性要求。该约束是其设备能力示例，不直接作为本平台通用硬编码校验。

移远部分采用公开技术文档作为能力参考，没有确认其当前控制台的具体布局与全部控件。

## 下一版重构任务

1. 建立可贯通的产品 → 模块 → 版本 → 包状态；版本表展示包类型、封存与验证状态，行操作随状态变化。
2. 包详情展示源／目标版本、文件、大小、校验值和构建阶段；已知大小时计算差分节省量。封存后更换文件创建新包，保留原记录。
3. 增加验证设备选择与验证结果详情；失败恢复回到对应阶段。构建重试与设备执行重试分别显示。
4. 保留四步向导；第二步用结构化选择和条件摘要，第三步分“时间安排／下发与确认／高级策略”，第四步展示可读执行摘要并可返回修改。
5. 批次详情以状态分布和任务表为主；点击状态筛选任务，详情展开每轮结果。无完整统计接口时只能显示“当前加载任务”，不能把当前页计数称为批次总数。

## 接口边界

当前 CreateReleaseVO 已有 sourceVersions、hardwareVersions、deviceIds、groupId、tags、priority、递增速率字段、effectiveFrom/effectiveUntil 和 execTime。groupId 明确仅直接成员且取交集；tags 为全部精确匹配；rateThreshold 为累计成功任务数。

匹配人数预估、排除原因汇总、批次统计、列表和规则回读需按实际查询契约确认，不能前端逐设备请求拼出结果。需要服务端聚合或批量返回，遵守禁止 N+1 的要求。独立的设备仅拉取开关、批次自定义重试与自动熔断未在此请求类发现，不能作为已支持能力。型号兼容、空间和电量等条件也须以自身后端和设备协议为准。
