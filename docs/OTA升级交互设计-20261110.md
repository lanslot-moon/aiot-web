## 信息架构与视觉

产品详情是固件配置的主入口，在现有产品局部导航中增加「固件与升级」。默认展示当前产品的固件模块，进入模块管理版本，在版本下配置一个或多个升级包，然后验证并创建升级计划。产品 ID 随页面上下文带入，选择设备、模块和版本时始终约束当前产品。项目侧栏的「OTA 升级」作为跨产品运维入口，承载发布计划和设备任务，并链接到对应产品的固件配置。设备详情可带设备 ID 进入升级任务。切换项目清除原项目的产品、发布、任务标识与筛选。

产品内建议路径为 `/projects/:projectId/products/:productId/firmware`，其下按模块、版本和包逐层进入。页面保持同一产品页头与局部导航，面包屑表达当前位置。模块创建用紧凑 Dialog，版本及包配置使用详情页，签名登记与操作确认使用 Dialog，设备执行记录用 Sheet。

## 后端能力对应的完整配置流程

2026-11-10 复核 `CreateModuleVO`、`RegisterFirmwareVO`、`CreatePackageVO`、`CreateDeltaBuildVO`、`CreateReleaseVO` 与服务层校验。下表路径为服务内部 HTTP 路径，浏览器接入时使用项目既有网关。

| 配置所在位置 | 用户操作与条件字段 | 已有接口 |
| --- | --- | --- |
| 产品 → 固件模块 | 新建模块，填写名称 `displayName`、标识 `moduleCode`、通道 `firmwareChannel`，自动带入 `productId`。通道非负且同产品唯一。 | `POST /ota/firmware/modules`，`GET /ota/firmware/modules?productId=…` |
| 模块 → 固件版本 | 新增版本号 `version`、说明 `description` 和硬件约束 `hardwareConstraintJson`，带入 `moduleId`。详情提供「发布固件版本」。 | `POST /ota/firmware/versions`，`GET /ota/firmware/versions?moduleId=…`，`POST /ota/firmware/versions/{id}/publish` |
| 版本 → 新建升级包 | 「包类型」使用整包／差分包单选。整包传 `FULL`，必填目标完整镜像 SHA-256。差分包传 `DELTA`，必填基础版本、源镜像 SHA-256、算法，目标镜像摘要可由差分构建回填。带入 `targetVersionId`。 | `POST /ota/packages`，`GET /ota/packages?targetVersionId=…` |
| 包 → 文件与封存 | 上传并确认文件后设置用途、顺序。获取清单摘要、登记签名、封存，逐步显示完成状态。 | `POST /ota/packages/{id}/files`，`GET /ota/packages/{id}/manifest-digest`，`POST /ota/packages/{id}/manifest-signature`，`POST /ota/packages/{id}/seal` |
| 差分包 → 构建 | 提供源、目标固件及源、目标文件，后台生成差分、还原校验并上传差分产物。提交后跟踪状态，支持取消、失败重试和查看构建轮次。 | `POST /ota/delta-builds`，`GET /ota/delta-builds/{id}`，对应 `/cancel`、`/retry`、`/attempts` |
| 包 → 样机验证 | 选择同产品测试设备，创建并启动验证，结果绑定该包清单。 | `POST /ota/verifications`，`POST /ota/verifications/{id}/start`，`GET /ota/verifications/{id}` |
| 版本／包 → 创建升级计划 | 产品、模块、目标版本、包自动带入。配置升级范围、灰度、升级方式、时间、速率及 App 确认。 | `POST /ota/releases`，保存后 `POST /ota/releases/{id}/activate` |
| 设备 → 可用升级 | 查看设备及固件通道的可用升级，发起或确认升级后跟踪该任务。 | `GET /ota/device-upgrades/available`，`POST /ota/device-upgrades/start`，`GET /ota/device-upgrades/task` |

### 升级时间与立即升级

创建升级计划的「升级策略」区同时展示以下三组设置，使用条件展开保持表单紧凑。

| 设置 | 界面行为 | 后端字段和约束 |
| --- | --- | --- |
| 发布生效时间 | 单选「立即生效 / 定时生效」，定时展开开始时间，可选结束时间。 | `effectiveFrom/effectiveUntil`。立即模式省略开始时间。预约仅静态发布可用，开始在 5 分钟至 7 天内，填写结束时间时，持续时间为 1 小时至 30 天。 |
| 升级方式 | 单选「提醒升级 / 静默升级 / 强制升级 / 主动检测」。四种方式作为可见业务配置。 | `upgradeType` 分别为 0、1、2、3。默认静默，按实际设备协议支持情况使用。 |
| 设备执行时间 | 选择静默升级后展开「立即执行 / 指定执行时间」。选择其他升级方式时收起执行时间并重置参数。 | `execTime`，0 表示立即执行，指定时间传 Unix 毫秒。服务只允许静默方式使用非零执行时间。 |
| App 确认 | 独立开关「需要用户确认后下发」，确认摘要中始终显示。 | `requireAppConfirm`，与升级方式分别提交。 |

确认页分别列出「发布生效时间」「设备执行时间」和「App 确认」，让操作者能判断计划何时进入调度、设备何时被要求执行。指定设备时间由设备按协议执行，界面展示真实进度。

范围配置完整覆盖 `mode`、`deviceIds`、`groupId`、`tags`、`sourceVersions`、`hardwareVersions` 和 `rolloutPercent`。推送策略提供「固定速率 / 按成功数量递增」，选择递增后展开初始速率 `pushPerMinute`、成功数量阈值 `rateThreshold`、每档增量 `rateStep` 和上限 `maxPushPerMinute`，上限至少等于初始速率。优先级 `priority` 放在高级配置，范围为 0–100。

版本详情的升级包表支持同一目标版本存在整包及来自不同源版本的差分包。创建计划时选择具体包，差分源版本限制出现在范围配置与确认摘要中。列表和详情按当前层级按需读取，禁止逐行补查子资源。

| 页面 | 首屏内容和操作 | 详细内容 |
| --- | --- | --- |
| 产品内固件管理 | 从当前产品进入，显示模块名称、标识、通道和状态。进入模块后按版本和状态筛选。 | 版本详情显示版本状态、说明及升级包表。包详情显示整包或差分、源与目标版本、文件清单、封存状态和验证入口。 |
| 发布计划 | 已知发布 ID 可打开详情。具备项目级发布列表后，展示产品、模块、目标版本、状态、灰度与生效时间，并提供对应筛选。 | 详情顶部展示状态和上下文，中间显示配置与执行计数，下方是可筛选的设备任务表。新建使用独立分步页面，激活、暂停、恢复和扩灰使用确认弹窗。 |
| 设备任务 | 按已授权的发布、验证或设备进入，筛选任务状态。显示设备 ID、任务状态、执行阶段、进度、轮次、更新时间。 | 点击任务打开 Sheet，查看错误码、关联来源及执行轮次。支持复制 ID 和跳转现有设备详情。 |

复用 `ProjectWorkspaceShell`、项目侧栏、面包屑、设备页的线形标签与 `GatewayDataTable`。保持 Lyra 的中性色、细分隔线和紧凑行距。状态用现有 Badge，颜色辅助状态文字。普通表单用现有 Input、Select 和 FieldError，反馈用 ErrorNotice、Empty 与 Sonner。移动端将筛选、按钮和摘要纵向排列，只让表格容器横向滚动。发布和验证详情支持刷新及深链接，后退回到来源的筛选和游标。

## 从固件到发布

### 1. 准备固件与升级包

- 选产品 → 创建固件模块或进入已有模块 → 登记版本。模块表单包含名称、标识、固件通道。版本表单包含版本号、说明和服务契约允许的硬件约束。将版本状态与包状态分别展示。
- 版本详情创建「整包」或「差分包」。差分包显式展示源版本、目标版本、源和目标镜像 SHA-256 及算法，源版本缺失时定位该字段。差分构建使用源和目标文件及固件 ID，显示构建状态和结果，打开构建详情才读取轮次。
- 复用 `IamFileUploader` 的私有对象上传和云端确认，随后把确认后的文件 ID、用途和顺序加入升级包。分别提示「文件已上传」与「文件已加入升级包」。任一步失败时保留已完成步骤与可重试入口。
- 文件准备好后，读取服务端清单摘要，登记可信签名方给出的签名，再请求封存。只展示摘要与验签结果，私钥留在签名方。版本发布动作可独立完成，文案使用「发布固件版本」，解释该动作使版本可用于创建发布计划。

### 2. 样机验证

- 在已封存升级包上选择「创建样机验证」。设备选择器限定在该包所属产品，提交去重后的设备 ID。创建完成进入验证详情，再点击「开始验证」。
- 验证状态为草稿、验证中、通过、失败。当前服务以测试设备全部成功判定通过，列表按 `sourceType=VERIFICATION&sourceId={id}` 读取设备任务。失败行可展开排查，并提供「重新创建验证」入口。批量重试的适用状态按设备任务契约处理，验证结论始终读取验证详情。
- 创建发布计划时，目标版本须已发布，当前 HTTP 创建契约必填指定包 ID，服务要求新建包已封存且通过与该清单摘要对应的验证。UI 不从「已封存」推断「验证通过」。缺少包级验证关联查询时，从已通过的验证详情带入包 ID，或由创建接口校验用户明确选择的已封存包并反馈到「升级包」字段。

### 3. 新建与激活发布

1. **选择版本。** 依次选择产品、模块、已发布版本与升级包，变更上游清除下游选择。确认区展示差分包的源版本限制及目标版本。
2. **限定范围。** 选「静态范围」或「动态匹配」。静态在激活时冻结设备候选范围，动态按发布规则持续匹配。可限定指定设备、静态分组、标签、源版本、硬件版本。条件取交集，静态分组只含直接成员，标签须全部匹配。显示规则摘要，实际人数以服务端匹配为准。初始灰度建议值取 5%，允许按实际情况输入 0–100 的整数。选择 100% 时确认文案明确是全部符合规则的设备。
3. **配置下发。** 常规表单显示发布生效时间、升级方式、设备执行时间、推送速率和 App 确认。静默方式展开立即执行或指定执行时间；递增速率展开阈值、增量及上限。静态发布可预约，开始须在提交后 5 分钟至 7 天内，指定结束时间时须在开始后 1 小时至 30 天内。动态发布可立即生效并设置结束时间。下发优先级放入高级设置。立即生效在激活后进入最近一轮服务端调度。
4. **检查并保存。** 摘要列出目标版本、升级包、范围条件、灰度比例、速率和时间。按钮为「保存发布草稿」。服务返回发布 ID 后进入详情，用户再点「激活发布」。同次创建保留在内存中的配置可辅助确认，刷新后持久化配置以服务端详情为准。

## 发布监控与任务处置

- 发布状态直接取服务端。已激活且开始时间在未来时辅以「待生效」，超过窗口辅以「下发窗口已结束」。发布暂停后停止后续投递，已经接收指令或开始安装的设备按实际回报推进。恢复、扩灰和修改速率前刷新状态。扩灰只能提高比例，展示旧值和新值，已暂停的发布仍保持暂停。当前灰度无法回读时，暂缓提供跨会话的扩灰操作，直到详情提供权威值。
- 发布计数来自 `GET /ota/monitor/releases/{releaseId}`。将 `matchedDevices` 标为「已生成任务」，失败数含超时。当前等待计数只含待确认、待下发及已通知。取消和等待重试未单独进入汇总，不能通过差值补齐状态分布。缺少时间序列时使用计数和明细。
- 任务状态依次区分待确认、待下发、已通知、执行中，以及等待重试、成功、失败、超时、已取消。执行中显示设备上报阶段（预检查、下载、校验、安装、重启、结果确认）和可用的进度。缺少进度显示「等待设备上报」。下载 100% 时仍展示当前阶段，成功标记取任务的 `SUCCEEDED`。
- 列表只勾选本页，显示已选数量和操作目标。待确认可确认，待确认／待下发／已通知可取消，失败／超时／等待重试可人工重试，服务端仍校验租约和发布窗口等约束。取消提示说明设备端安装的边界。单任务重试同样调用批量重试并传单个任务 ID。批量最多 200 项，整批校验，失败时保留选择并刷新可操作状态。
- 任务 Sheet 默认显示当前轮次及失败码，展开后读取 `GET /ota/tasks/attempts?taskId=…`。刷新仅针对打开的详情与当前页，窗口隐藏、切换项目或到达终态后停止相应轮询。统计与任务页请求独立处理失败。操作超时时提示「结果待确认」，已知 ID 时先重查。创建超时且未拿到 ID 时保留表单，避免自动重复创建。

## 联调契约与待补能力

| 能力 | 当前源码与实现边界 |
| --- | --- |
| 固件、升级包 | `IOtaFirmwareApiService` 提供模块与版本查询及创建、版本发布。 `IOtaPackageApiService` 提供包列表、详情、挂载文件、获取清单摘要、登记签名及封存。版本列表带模块 ID，包列表带目标版本 ID。 |
| 差分构建与验证 | `IOtaDeltaBuildApiService` 和 `IOtaVerificationApiService` 支持创建及按 ID 查询。缺少按升级包反查列表与最近结果的公开查询。接入前可从当次创建响应进入详情或用已知 ID 打开；包详情恢复历史及展示权威验证结果需要补查询。 |
| 发布计划 | `IOtaReleaseApiService` 支持创建、按 ID 查询、激活、暂停、恢复、扩灰、调整速率。缺少项目级发布列表，`ReleaseVO` 未返回包 ID、范围规则、当前灰度和速率。完整列表与详情复盘依赖项目级游标列表和规则读取。服务内部的停止方法没有对应管理 HTTP 入口。 |
| 预览与网关 | 未发现发布候选人数或不符合原因的预检接口。确认页展示配置事实，不预测命中量。联调时核对实际网关路径、项目归属校验和读写权限码，再开放项目菜单及写操作。沿用现有认证请求客户端，浏览器不传可信用户或租户头。 |
| 分页与批量查询 | OTA 列表使用 `afterId/pageSize` 与 `items/nextCursor/hasMore`，默认 50，最大 200。筛选变更重置游标。列表只读本页，当前页显示接口已返回的 ID 或共享字典信息。需要补名称或关联摘要时使用项目范围的批量查询，禁止按行请求包详情、设备详情、发布详情或轮次。 |

## 实现验收

- 样机失败、源版本不匹配、签名失败、无权操作和项目切换均可从界面看出原因与下一步。草稿、激活、暂停、恢复、下载完成和升级成功各有独立状态。
- 在约 1280×800 与 390×844 两种视口检查现有主题、表格滚动和操作可达性。键盘可完成表单及确认操作，弹窗关闭后焦点回到触发按钮。首次加载、空列表、筛选无结果、后台刷新失败、提交中和提交冲突分别验收。
- 实现接入后用网关实际响应验证游标、权限、批量状态更新与缓存刷新。按发布查看任务时同传 `sourceType`、`sourceId`。跑前端 lint、构建及桌面与移动端浏览器验证。
